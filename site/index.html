Avant de commencer

Le MCP Prisme.ai est un petit serveur local que votre assistant IA lance en arrière-plan. Il appelle l'API Prisme.ai avec vos propres droits : l'assistant voit et fait exactement ce que votre compte permet, rien de plus.

Node.js 18 ou plus

Le serveur MCP s'exécute avec node. Aucune autre installation n'est nécessaire.

Un compte Prisme.ai

Avec accès au Studio de votre environnement, par exemple studio.prisme.ai.

Un client MCP

Claude Code, Codex, VS Code Copilot, Claude Desktop, Cursor ou tout autre client compatible.

Vérifiez que Node.js est bien disponible dans un terminal :

Terminal
node --version
# Attendu : v18.x.x ou supérieur

Si la commande est introuvable, installez Node.js depuis nodejs.org (ou via nvm / fnm), puis ouvrez un nouveau terminal.

i

Lancez votre outil depuis un terminal. Une application ouverte depuis le Dock ou le menu Démarrer ne voit pas toujours le Node.js installé dans votre profil de shell. En cas de doute, démarrez-la depuis le terminal où node --version fonctionne.

1

Installer le MCP dans votre outil

Choisissez votre outil. Claude Code, Codex et VS Code Copilot installent le MCP comme un plugin en deux commandes. Les autres clients pointent directement vers le serveur.

Claude Code

  1. Ajoutez la marketplace Prisme.aiDans une session Claude Code, tapez :
    Claude Code
    /plugin marketplace add prismeai/prismeai-mcp
  2. Installez le plugin
    Claude Code
    /plugin install prisme-ai@prismeai-mcp
  3. RechargezSi les outils n'apparaissent pas tout de suite, tapez /reload-plugins ou redémarrez la session.
✓

Le plugin apporte le serveur MCP prisme-ai-builder et des skills prêts à l'emploi, par exemple /prisme-ai:guide qui présente tout ce qui est disponible.

Codex

  1. Ajoutez la marketplace et le pluginDepuis un terminal :
    Terminal
    codex plugin marketplace add prismeai/prismeai-mcp
codex plugin add prisme-ai@prismeai-mcp
  2. Démarrez une nouvelle session CodexOu redémarrez l'application de bureau pour charger le plugin.
i

Codex peut charger les outils MCP à la demande : formulez une demande qui concerne clairement Prisme.ai (« liste mes workspaces Prisme.ai sur prod ») pour qu'il les active.

VS Code Copilot

Nécessite une version de VS Code qui prend en charge les agent plugins.

  1. Déclarez la marketplaceOuvrez la palette de commandes, lancez Preferences: Open User Settings (JSON) et ajoutez :

  3. C'est prêtLe serveur prisme-ai-builder démarre dès que le plugin est activé. Utilisez Copilot Chat en mode Agent.

Pour toute une équipe

Installation manuelle (si les plugins sont bloqués chez vous)

Clonez le dépôt (voir l'onglet Claude Desktop), puis ouvrez MCP: Open User Configuration. Notez que VS Code utilise la clé servers, pas mcpServers :

mcp.json
{
  "servers": {
    "prisme-ai-builder": {
      "type": "stdio",
      "command": "node",
      "args": ["/chemin/absolu/vers/prismeai-mcp/plugin/build/index.js"],
      "env": {
        "PRISME_CONFIG_DIR": "${userHome}/.prisme-ai-mcp"
      }
    }
  }
}

Démarrez ensuite le serveur avec MCP: List Servers → Start Server. Cette méthode fournit les outils, mais pas les skills du plugin.

2

Créer un jeton d'accès

Le MCP s'authentifie avec un jeton d'API personnel, créé depuis le Studio de votre environnement.

  1. Ouvrez la page des jetonsConnectez-vous au Studio puis rendez-vous sur /settings/tokens. En production : studio.prisme.ai/settings/tokens. Sur l'hébergement OVH : studio.fr.prisme.ai/settings/tokens.
  2. Créez un jetonDonnez-lui un nom explicite, par exemple « MCP – Claude Code – poste perso », pour pouvoir le révoquer facilement plus tard.
  3. Copiez-leGardez-le dans votre presse-papiers pour l'étape suivante. Il ne sera plus affiché ensuite.
!

Ne collez jamais ce jeton dans la conversation avec l'assistant. Tout ce que vous écrivez dans le chat est transmis au fournisseur du modèle d'IA. L'étape 3 enregistre le jeton directement sur votre poste, sans passer par le chat.

3

Enregistrer le jeton sur votre poste

La commande set-token s'exécute dans votre propre terminal. Elle demande le jeton en saisie masquée, le vérifie auprès de Prisme.ai, puis l'enregistre localement (fichier credentials.json, lisible par vous seul).

✓

Le plus simple : demandez quelque chose à votre assistant, par exemple « Liste mes workspaces Prisme.ai sur prod ». Tant qu'aucun jeton n'est enregistré, le MCP répond avec la commande exacte à copier, chemins compris. Collez-la dans votre terminal.

Choisir le nom d'environnement

Bac à sable Prisme.ai (sandbox.prisme.ai)sandboxhttps://api.sandbox.prisme.ai/v2

Lancer la commande

La forme générale est la suivante. Gardez-la sur une seule ligne et ne coupez pas les chemins entre guillemets :

Terminal
node "<serveur>/build/index.js" set-token prod --config-dir "<dossier-de-config>"

Hébergement OVH : cet environnement n'est pas préconfiguré dans le MCP. Ajoutez ses deux URL à la commande :

Terminal · OVH
node "<serveur>/build/index.js" set-token ovh --api-url https://api.studio.fr.prisme.ai/v2 --studio-url https://studio.fr.prisme.ai --config-dir "<dossier-de-config>"
Outil<serveur><dossier-de-config>
Claude Code~/.claude/plugins/cache/prismeai-mcp/prisme-ai/<version>~/.claude/plugins/data/prisme-ai-prismeai-mcp
CodexUtilisez la commande affichée par le MCP lors de votre première demande.
VS Code (plugin)Affiché par le MCP lors de votre première demande~/.prisme-ai-mcp
Claude Desktop, Cursor, autres/chemin/absolu/vers/prismeai-mcp/plugin~/.prisme-ai-mcp

La commande vous pose ensuite quelques questions :

  1. Le jetonCollez-le : rien ne s'affiche à l'écran, c'est normal.
  2. Les URL de l'API et du StudioValidez les valeurs proposées pour prod ou sandbox. Pour ovh, elles sont déjà fournies par la commande ci-dessus.
  3. Un certificat d'entreprise (facultatif)Laissez vide, sauf si votre réseau passe par un proxy qui inspecte le trafic HTTPS : indiquez alors le chemin du fichier .pem fourni par votre service informatique.

Si le jeton est valide, il est enregistré et pris en compte immédiatement : aucun redémarrage n'est nécessaire. Un jeton invalide n'est jamais enregistré.

Instance dédiée ou auto-hébergée

Donnez un nom à votre environnement et précisez ses URL en une seule commande :

Terminal
node "<serveur>/build/index.js" set-token mon-instance --api-url https://api.mon-domaine.com/v2 --studio-url https://studio.mon-domaine.com --config-dir "<dossier-de-config>"
  • L'URL de l'API doit se terminer par /v2.
  • Ajoutez --node-extra-ca-certs /chemin/vers/ca-entreprise.pem si votre instance utilise un certificat interne.
  • La commande doit pouvoir joindre l'API depuis votre poste (VPN actif, par exemple).

Mentionnez ensuite ce nom dans vos demandes : « … sur mon-instance ».

Plusieurs environnements

Relancez simplement set-token une fois par environnement (prod, sandbox, mon-instance…), chacun avec son propre jeton. Précisez ensuite l'environnement voulu dans chaque demande. Si vous nommez un environnement non configuré, le MCP s'arrête au lieu d'en utiliser un autre.

4

Vérifier que tout fonctionne

  1. Les outils sont visiblesDans Claude Code, tapez @ ou /mcp : le serveur prisme-ai-builder doit apparaître comme connecté. Dans les autres outils, cherchez-le dans la liste des serveurs ou des outils MCP.
  2. Une première demandeEssayez par exemple :
    Liste mes workspaces Prisme.ai sur prod.
    Montre-moi les automations du workspace « nom-du-workspace » sur prod.
    Cherche dans la documentation Prisme.ai comment déclencher une automation par webhook.
  3. Pour aller plus loinDans Claude Code ou Codex, lancez /prisme-ai:guide pour découvrir les skills fournis, et /prisme-ai:prisme-mcp-setup pour vous faire accompagner dans la configuration des environnements.
i

Astuce : indiquez toujours l'environnement (« sur prod », « sur ovh », « sur sandbox ») dans vos demandes. Par défaut, le MCP cible le bac à sable.

Dépannage

Aucun outil Prisme.ai n'apparaît, et aucun message d'erreur

Votre outil n'a pas trouvé node au démarrage. Il ne réessaie pas pendant la session.

  1. Vérifiez que node --version fonctionne dans le terminal d'où vous lancez l'outil.
  2. Redémarrez l'outil après avoir installé Node.js. Dans ce cas précis, set-token seul ne suffit pas.
  3. Enregistrez ensuite le jeton (étape 3).

Sous VS Code, lancez l'éditeur avec code . depuis un terminal, désactivez puis réactivez le plugin, et consultez MCP: Show Output pour voir l'erreur de démarrage.

« No credentials », jeton manquant ou erreur 401

Aucun jeton n'est enregistré pour cet environnement, ou il a expiré ou été révoqué. Créez un nouveau jeton (étape 2), puis relancez la commande set-token indiquée dans le message d'erreur. Elle remplace l'ancien jeton.

Erreur 403 sur un workspace

Le jeton fonctionne, mais votre compte n'a pas les droits sur ce workspace. Demandez l'accès au propriétaire du workspace, ou vérifiez que vous ciblez le bon environnement.

« Environnement inconnu » ou non configuré

Le nom d'environnement utilisé dans la demande n'existe pas dans votre configuration. Vérifiez l'orthographe (prod, sandbox…) ou déclarez-le avec set-token et l'option --api-url.

Erreur de certificat ou de connexion (réseau d'entreprise)

Si votre entreprise inspecte le trafic HTTPS, Node.js doit connaître son certificat. Relancez set-token en indiquant le fichier .pem fourni par votre service informatique (question posée par la commande, ou option --node-extra-ca-certs). Vérifiez aussi que votre VPN est actif si votre instance n'est accessible qu'en interne.

J'ai collé mon jeton dans le chat par erreur

Révoquez-le immédiatement depuis /settings/tokens dans le Studio, créez-en un nouveau et enregistrez-le avec set-token dans votre terminal.

Codex ne semble pas utiliser les outils Prisme.ai

Codex peut charger les outils MCP à la demande. Formulez une demande qui mentionne explicitement Prisme.ai et l'environnement, ou démarrez une nouvelle session après l'installation.

?

Toujours bloqué ? Contactez le support Prisme.ai en précisant votre outil, sa version, la sortie de node --version et le message d'erreur affiché, sans jamais inclure votre jeton.

Before you start

The Prisme.ai MCP is a small local server that your AI assistant runs in the background. It calls the Prisme.ai API with your own permissions: the assistant sees and does exactly what your account allows, nothing more.

Node.js 18 or later

The MCP server runs with node. Nothing else needs to be installed.

A Prisme.ai account

With access to the Studio of your environment, for example studio.prisme.ai.

An MCP client

Claude Code, Codex, VS Code Copilot, Claude Desktop, Cursor or any other compatible client.

Check that Node.js is available in a terminal:

Terminal
node --version
# Expected: v18.x.x or later

If the command is not found, install Node.js from nodejs.org (or with nvm / fnm), then open a new terminal.

i

Start your tool from a terminal. An application opened from the Dock or the Start menu does not always see the Node.js installed in your shell profile. If in doubt, start it from the terminal where node --version works.

2

Create an access token

The MCP authenticates with a personal API token, created from the Studio of your environment.

  1. Open the tokens pageSign in to the Studio and go to /settings/tokens. In production: studio.prisme.ai/settings/tokens. On the OVH hosting: studio.fr.prisme.ai/settings/tokens.
  2. Create a tokenGive it a clear name, for example “MCP – Claude Code – laptop”, so you can easily revoke it later.
  3. Copy itKeep it in your clipboard for the next step. It will not be shown again.
!

Never paste this token into the conversation with the assistant. Everything you type in the chat is sent to the AI model provider. Step 3 stores the token directly on your machine, without going through the chat.

3

Register the token on your machine

The set-token command runs in your own terminal. It asks for the token with hidden input, checks it against Prisme.ai, then stores it locally (in a credentials.json file readable only by you).

✓

The easiest way: ask your assistant something, for example “List my Prisme.ai workspaces on prod”. As long as no token is registered, the MCP replies with the exact command to copy, paths included. Paste it into your terminal.

The command then asks a few questions:

  1. The tokenPaste it: nothing appears on screen, that's expected.
  2. The API and Studio URLsAccept the suggested values for prod or sandbox. For ovh, they are already provided by the command above.
  3. A corporate certificate (optional)Leave empty, unless your network goes through a proxy that inspects HTTPS traffic: then enter the path of the .pem file provided by your IT team.

If the token is valid, it is saved and used immediately: no restart is needed. An invalid token is never saved.

Dedicated or self-hosted instance

Name your environment and give its URLs in a single command:

Terminal
node "<server>/build/index.js" set-token my-instance --api-url https://api.my-domain.com/v2 --studio-url https://studio.my-domain.com --config-dir "<config-dir>"
  • The API URL must end with /v2.
  • Add --node-extra-ca-certs /path/to/company-ca.pem if your instance uses an internal certificate.
  • The command must be able to reach the API from your machine (VPN on, for example).

Then mention that name in your requests: “… on my-instance”.

Several environments

Simply run set-token once per environment (prod, sandbox, my-instance…), each with its own token. Then name the environment you want in each request. If you name an environment that is not configured, the MCP stops instead of using another one.

Troubleshooting

No Prisme.ai tools show up, and there is no error message

Your tool could not find node when it started. It does not retry during the session.

  1. Check that node --version works in the terminal you launch the tool from.
  2. Restart the tool after installing Node.js. In this specific case, set-token alone is not enough.
  3. Then register the token (step 3).

In VS Code, launch the editor with code . from a terminal, disable then re-enable the plugin, and check MCP: Show Output for the startup error.

“No credentials”, missing token or 401 error

No token is registered for this environment, or it has expired or been revoked. Create a new token (step 2), then run the set-token command shown in the error message again. It replaces the old token.

403 error on a workspace

The token works, but your account has no rights on this workspace. Ask the workspace owner for access, or check that you are targeting the right environment.

“Unknown” or unconfigured environment

The environment name used in the request does not exist in your configuration. Check the spelling (prod, sandbox…) or declare it with set-token and the --api-url option.

Certificate or connection error (corporate network)

If your company inspects HTTPS traffic, Node.js needs to know its certificate. Run set-token again and give the .pem file provided by your IT team (asked by the command, or with the --node-extra-ca-certs option). Also check that your VPN is on if your instance is only reachable internally.

I pasted my token into the chat by mistake

Revoke it right away from /settings/tokens in the Studio, create a new one and register it with set-token in your terminal.

Codex does not seem to use the Prisme.ai tools

Codex may load MCP tools on demand. Phrase a request that explicitly mentions Prisme.ai and the environment, or start a new session after installing.

?

Still stuck? Contact Prisme.ai support with your tool, its version, the output of node --version and the error message shown, never including your token.
